# 子任务：面板与限额切到周期值（前端 + 文案）

## 目标

把"用户看到的用量"从**累计值**切到**本周期值**，累计值保留为历史统计并明确标注；未配置周期的节点保持旧行为。

## 要求

1. **单一数据来源**：面板与限额只认服务端周期字段（`net_period_up` / `net_period_down` / `period_started_at`）；
   **不得**在前端按"1 号"或浏览器时区自行推算边界；不得在多个组件各算一遍（提炼成一个工具函数/上下文）。
2. **展示口径**：卡片、节点详情、进度条统一为「本周期已用 / 限额」；累计值单独标注为「累计（历史）」。
3. **限额判定**：`traffic_limit` + `traffic_limit_type`（`sum`/`up`/`down`/`max`/`min`）与**周期值**组合；
   超额/告警阈值（如 80%）也按周期值；口径必须写进文档。
4. **未配置周期**（`traffic_reset_day = 0` / `period_started_at` 为空且无周期）⇒ **行为与升级前逐项一致**（仍按累计值算百分比）。
5. **存量节点**：`period_started_at` 为空 ⇒ 显示"本周期尚未开始"（按 0），不得 NaN / 除零 / 异常动画。
6. **文案**：所有"已用/限额"位置区分"本周期 / 累计"；边界时区在 UI 说明（示例格式：「每月 22 日 00:00（America/New_York）重置」——
   **时区名必须来自节点配置**，不要硬编码，也不要写死某个地区）；5 个语言包同步（en / zh_CN / zh_TW / ja_JP / id_ID）。
7. **存量超额节点**（按累计已超额、按周期未超额）行为要显式定义：**以周期为准**，并在 UI 标注一次"口径已切换"（实现方式自定，需可复核）。

## Acceptance Criteria

- [ ] 类型检查：`npx tsc -p tsconfig.app.json --noEmit` 与 `npx tsc -p tsconfig.node.json --noEmit` 均 0 错误；
- [ ] 前端产物重建：`./scripts/build-frontend.sh` 成功且 `FRONTEND_TREE_SHA256` 更新（若改了 `frontend/**`）；
- [ ] 未配置周期节点的百分比与改动前**逐项一致**（用同一组输入对比，贴出前后数值）；
- [ ] `period_started_at` 为空时页面不出现 NaN / 0 除 / 负值（贴截图或 DOM 断言）；
- [ ] 5 个语言包键齐（缺键会让面板显示原始 key，必须核对）；
- [ ] 给出一组可复核命令（含只读 SQL 与面板字段对照）；
- [ ] 不顺手重构无关模块；不改 `database/**` 的累计写入语义。
