# 文档：脱离上游的独立维护声明与依赖安全自查规则

## 需求

1. 在 `ops-docs/` 写定独立维护规则（`INDEPENDENCE.md`）：
   - 决策声明：本仓为唯一权威来源；**内核与主题均不再跟随任何上游**；写清后果（上游新功能与安全修复不再自动获得、需自行判断搬运）；
   - 版本线规则：内核 `0.0.24+own.N`（前缀 = 最后一次对齐的上游版本）、主题自有线 `0.0.x`、标签 `server/v<版本>` 与 `theme-ink/v<版本>`；
   - 逃生通道（非常态、需授权）：临时 upstream remote → `cherry-pick`/`merge` → 评审合入 → 用完移除；不设常态 remote、不做定时同步；
   - 依赖安全自查：`go list -m -u all`、`govulncheck ./...`（未安装时给替代做法）、主题侧 `bun audit`；频率建议与"评估→升级并构建验证→部署"三步处理法。
2. `README.md` 顶部加一句话指向该文档。

## 验收标准

- 文档覆盖上述四项且命令可直接照做；
- README 顶部有指向；
- 提交带 `[task:<slug>]` 并推送成功；`git status` 干净；
- **不改内核代码、不跑构建、不动线上**。

## 非目标

- 不改任何代码；不新增依赖；不执行联网审计命令（仅在文档中给出，供需要时运行）。
