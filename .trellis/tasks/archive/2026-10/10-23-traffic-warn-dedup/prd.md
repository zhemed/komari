# 流量周期：非法配置 WARN 去重

## 背景（实测）

库里存在**非法**周期配置（外部改库所致；API 已能拦住）时，`AccumulateTraffic` 会走 `periodConfigInvalid` 分支：
跳过周期记账、**保留现值不销毁数据**、并打一条 WARN。实测（临时实例）：
- 每**一次上报**打 1 条 WARN（连续两次上报 = 2 条），长期非法配置会**刷屏**；
- 配置改回合法值后，记账立刻恢复。

## Goal

把 WARN 做成**去重**：同一节点、同一"配置指纹"只告警一次；配置值变化（指纹变化）时重新告警一次；
配置恢复合法后清理该节点的去重状态。

## 需求

1. **有界**：去重状态不得随节点数/时间无界增长（节点删除或配置恢复后要能清理）。
2. **指纹**：至少包含 `reset_day` 与 `timezone`；两者任一变化 ⇒ 视为新指纹 ⇒ 允许再告警一次。
3. **不改变既有语义**：累计与周期字段的行为、`disabled` 的"周期列清空"不变量、`invalid` 的"保留现值"都必须不变。
4. **可观测**：仍使用现有 `utils/log` 的 WARN 级别与模块名；日志内容保留 uuid / reset_day / timezone / 错误信息。
5. **并发安全**：不得引入数据竞争（`AccumulateTraffic` 可能并发进入；仓库既有 `trafficMu`，新状态要有自己的同步或复用）。

## Acceptance Criteria

- [ ] 同一非法配置连续 N 次上报 ⇒ **只 1 条 WARN**（测试断言计数）；
- [ ] 非法值变化（例如 `32` → `99`，或时区 `Asia/Nowhere` → `Bad/Zone`）⇒ **重新出现 1 条** WARN；
- [ ] 配置改回合法 ⇒ 记账恢复，且去重状态被清理（再次变非法时能重新告警）；
- [ ] 节点被删除（`DeleteTrafficTotal` 路径）⇒ 去重状态一并清理，不泄漏；
- [ ] 累计/周期数值行为与改动前逐字节一致（原有 20 个用例全绿）；
- [ ] `go build ./... && go vet ./... && go test ./... -count=1` 全绿；`./scripts/check-repo.sh --full` 全绿；
- [ ] 新用例**先在未去重版本上跑出 FAIL**（红→绿证据），证明它真的在测去重。

## Constraints

- 只动 `database/clients/`（如需在 `DeleteTrafficTotal` 挂钩，也在该包内）；
- 不顺手重构无关模块；不改前端；不改文档（文档由 Lead 安排）；
- 不碰生产、不发版（发版另行决定）；
- 提交带 `[task:traffic-warn-dedup]`。
