# 把面板展示与限额判定切到服务端周期值（父任务）

## 用户要求（原文要点）

- 面板展示改为「**本周期已用 / 限额**」（卡片、详情、进度条一致）；
- **限额判定**（超额、告警阈值、阻断）也改为基于**周期值**；
- **累计值保留**为"总流量/历史统计"，两者并存且**明确标注口径**；
- 未配置周期（`traffic_reset_day = 0`）的节点**保持旧行为**，不得回归。

## 现状

- 服务端已按「重置日 + 时区」算周期边界，跨边界归零 `period_up/period_down` 并写 auditlog；
- RPC `getNodesLatestStatus` 已追加 `net_period_up` / `net_period_down` / `period_started_at`；
- **缺口**：面板卡片与限额进度读的仍是**累计值** ⇒ 用户看到"数字永不下降"
  （实例实测：累计 544.75 GB / 限额 1 TiB = 49.54%，而同期周期值仅 0.02 GB）。

## 任务拆解（子任务）

| 子任务 | 内容 | 依赖 |
|---|---|---|
| `10-23-period-panel-frontend` | 前端：卡片/详情/进度条改周期值、限额判定口径、文案与标注、5 语言包 | 依赖服务端字段（已存在） |
| `10-23-accumulate-stall-heartbeat` | 生产累加批处理停摆排查 + 心跳暴露 | 独立（可与前者并行） |

## 跨子任务验收（父任务负责最终集成复核）

- [ ] 跨周期用例：构造跨过重置日 ⇒ 面板与限额进度切到新周期值（≈0 起），累计仍单调增长；
- [ ] 未配置周期的节点行为与升级前**逐项一致**（回归）；
- [ ] 存量节点（`period_started_at` 为空 → 首次启用）显示正确、无 NaN/异常态；
- [ ] 限额判定口径有文档说明，超额/告警阈值按新口径实测；
- [ ] UI 上"本周期 / 累计"均有明确标注；边界时区在 UI 说明；
- [ ] 累计值写入语义**未改**（只读校验：`SELECT up_total, down_total, period_up, period_down, period_started_at, needs_rebaseline FROM client_traffic_totals`）；
- [ ] 停摆异常有结论（根因或明确的复现条件）+ 心跳可见。
