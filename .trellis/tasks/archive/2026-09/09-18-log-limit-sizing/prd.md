# 日志上限取值建议（docker logging）

## Goal

用户在定版阶段问："加日志上限你看看多少比较合适"。要求给**有依据**的取值，不是拍脑袋。

## Requirements

- **R1** 先摸清日志来源：面板日志页读哪一路、stdout 由什么驱动、空载是否有输出。
- **R2** 实测速率：空载、面板常开、逐次请求、页面浏览；agent 上报路径要区分 v1(POST)/v2(WS)。
- **R3** 给出建议值 + 不同部署规模下的可回溯时长，并说明不建议更小/更大的理由。
- **R4** 结论不得越界：不读 `/var/lib/docker` 等宿主机文件（工作区外），封装开销按格式推算并标注。
- **R5** 流程走完并归档。

## Acceptance Criteria

- [x] 实测数据与推算表（`research/findings.md`）
- [x] 建议 `max-size/max-file` 及适用/不适用场景
- [x] 测试容器与临时目录清理干净（`docker ps -a` 无残留）
- [ ] journal + 归档

## Out of Scope

- 不改仓库代码/文档（是否把建议写进 README 由用户定）；
- 不在用户宿主机实际部署。
