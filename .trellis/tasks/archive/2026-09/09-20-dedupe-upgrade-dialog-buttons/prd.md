# 升级弹窗按钮去重 → 0.0.21

## 用户发现

其他机器升级时，弹窗里列表首项的「安装此版本」（红框）与底部「立即升级（容器内替换）到 0.0.20」
指向**同一版本**，重复。

## 核查结论

两者都来自同一个 `latestRelease`：列表按 release 逐行渲染按钮，底部按钮固定用列表首项
（`latestRelease?.tag_name || latestRelease?.name`）。所以**最新版那一行确实重复**；
其余行是"指定版本/回滚"入口，功能不重复。

## 用户选择

- 去重方式：**列表里的按钮全部删掉，只留底部大按钮**
- 版本：**发 0.0.21**

## 改动

- `AdminPanelBar.tsx`：删除 release 列表每行的「安装此版本 / 复制升级命令」按钮块；
  列表仍展示所有可用版本与说明。
- 保留：底部按钮的两种形态（可自动升级 → 「立即升级…」；不支持 → 「复制升级命令」），
  以及 `canAutoUpgrade` / `isDockerRecreate` / `isContainerReplace` 的既有用法（无死变量）。
- 版本字面量 → 0.0.21；前端产物重建，`FRONTEND_TREE_SHA256` → `f4785c5b…`。
- 发布说明写清代价：**不再能从列表选特定版本/回滚**（改用 `install-komari.sh` 或二进制备份）。

## 顺带修掉的既有问题（同一任务内）

- `docs/MAINTAINING.md` §1 版本表还写着 `0.0.18`（回滚带回的旧内容，0.0.19/0.0.20 两次升级漏改）；
  现在 §1 增加显式一行 `**当前版本：\`0.0.21\`**`。
- `check-repo.sh` 第 1 项原先匹配标题里的"当前 **x**"写法，形同虚设；改为精确匹配上面那行。
  实现坑：模式里的 backtick 在双引号内被 shell 当**命令替换**，导致 `${VER}` 被替换成空、
  永远匹配失败——已用 `\`` 转义。
