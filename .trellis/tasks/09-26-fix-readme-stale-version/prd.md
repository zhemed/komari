# 修 README 过期版本号并加自检护栏

## 用户提问

「…（当前 0.0.18）。这是最新吗」——README 第 3 行声明的版本与事实不符。

## 事实核查（真源）

| 来源 | 值 |
|---|---|
| `scripts/version.env` | `0.0.21` |
| 最新 tag / release | `0.0.21`（Latest） |
| 镜像 `:latest` | 实测报 `0.0.21` |
| 生产 | `version=0.0.21`，hash `3977f5a7ee4b…` |
| `docs/MAINTAINING.md` | 正确（`当前版本：\`0.0.21\``） |
| **README 第 3 行** | **过期：写着 0.0.18**（0.0.19/0.0.20/0.0.21 三次升版都没同步它） |

结论：**README 那句是陈旧文案，最新是 0.0.21。**

## 根因

`check-repo.sh` 第 1 项只管 `docs/MAINTAINING.md`（且原先匹配的是标题写法，形同虚设），
**从不校验 README**——所以 README 里写死的版本号漂了三版都没人发现。

## 改动

1. `README.md`：`（当前 0.0.18）` → `（当前 0.0.21）`。
2. `check-repo.sh` 第 1 项扩展：**两处都查**——MAINTAINING 的 `**当前版本：\`x\`**` 与
   README 的 `（当前 x）`，任一与 `version.env` 不一致即报红；一致时额外给一条"文档版本声明一致"。

## 判别性验证（实测）

- 把 README 改回 `0.0.18` → 第 1 项报红：`README 的当前版本声明是 0.0.18，与 version.env（0.0.21）不一致`；
- 还原 `0.0.21` → 通过。

## 验收

- [x] README 与 MAINTAINING 均与 `version.env` 一致（自检第 1 项逐条打印）
- [x] 判别性验证有效（伪造漂移被当场抓住）
- [x] `check-repo.sh --full` 全绿

## 备注

本次只改文档与自检脚本，**不改运行代码、不发版**（前端产物/二进制不受影响）。
