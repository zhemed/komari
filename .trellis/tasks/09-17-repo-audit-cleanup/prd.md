# 仓库体检：清理、整理与进度对齐

## Goal

用户 2026-09-17 要求："检查我们的 komari 仓库，清理和整理还要对齐当前进度"。

目标是让仓库回到**自洽**状态：没有无主/过时/重复的产物与文件，文档口径与代码真实行为、
已发布版本、已落地的流程（三层 Trellis 闸门）一致。

## 方法（分两步，先体检后动手）

**第一步 只读体检**，产出分类清单，每一条都带证据（命令 + 输出）：
1. 版本与发布：`scripts/version.env` 的 `0.0.16` ↔ 8 处版本字面量 ↔ 最新 release ↔ 镜像 tag；
2. 仓库卫生：未跟踪/被忽略文件、`.build/`、`dist/`、`bin/`、`data/`、临时文件、大文件；
3. Git 状态：分支（含 `backup/pre-rewrite` 之类遗留）、tag、stash、与 origin 的差异；
4. 文档口径：README / MAINTAINING 里"当前版本""已知遗留""能力矩阵"是否与真实状态一致
   （重点：0.0.13+ 容器升级、§7 遗留清单、CI 存在性、agent 版本线）；
5. 代码与脚本：TODO/FIXME、已移除功能（插件系统 / 通知 / jsruntime）的残留引用、
   无脚本引用的孤立脚本、死代码；
6. Trellis 自身：活动/归档任务、journal 与索引、spec 与现实的偏差。

**第二步 按风险分级处理**：
- **A 类（可直接做）**：文档口径修正、无引用残留文件删除、目录归位、索引补齐；
- **B 类（需确认）**：删分支/tag、删历史产物、改发布资产、动 git 历史。

## Requirements

- **R1** 体检结论必须逐条带证据（命令 + 关键输出），不写"看了一眼没问题"。
- **R2** 清理只处理**能证明无引用**的东西；删任何文件前先给出"谁引用了它/谁没引用"的证据。
- **R3** 文档对齐要覆盖**所有落点**（README、MAINTAINING、spec、AGENTS、安装脚本注释），
  按 `.trellis/spec/guides/evidence-and-claims-guide.md` 的"全落点同步"清单执行。
- **R4** B 类动作先列给用户确认，不擅自执行。
- **R5** 全流程遵守 `AGENTS.md` 强制规则（本任务即是），提交带 `[task:repo-audit-cleanup]`；
  完成后 `check-repo.sh --full` 全绿 + journal + 归档。

## Acceptance Criteria

- [ ] 体检清单入库（本任务目录下 `research/findings.md`），A 类项全部处理完
- [ ] B 类项列给用户并得到答复
- [ ] 版本/发布/镜像/文档四处口径一致（逐条命令验证）
- [ ] `./scripts/check-repo.sh --full` 11 项全绿；闸门审计通过
- [ ] journal + 任务归档

## Out of Scope

- 不发新版本（除非体检发现必须靠发版才能修的口径问题，那样先汇报）；
- 不重构功能代码（只清死代码/残留引用，行为不变）。
