# 方案 B：服务端算流量周期

## 背景与裁决

- 「按月重置」目前只是 agent 侧上报口径（`--month-rotate`），服务端把上报值当**单调计数器**，
  跨重置日的下降被判为"计数器归零"⇒ 增量 0 ⇒ 累计值只增不减（排查见归档任务
  `archive/2026-10/10-23-traffic-month-rotate` 的 `research/findings.md`）。
- 用户裁决（2026-10-23）：**走方案 B**——服务端定义周期边界，agent 回报单调计数器；
  **面板展示口径不改**（继续显示累计值）。
- 流量虚高 2.12× 按用户裁决移出范围。

## Goal

让"按月重置"在服务端真正生效：服务端按节点级配置（重置日 + 时区）自行计算周期边界与周期用量；
累计值语义保持不变（面板无需改动）。

## 需求

1. **节点级配置**：每个节点可设「流量重置日」（`1..31`，`0` = 禁用）与「时区」（IANA 名称）。
2. **校验要硬**：越界/非法值必须**拒绝保存并报错**，不得静默退化成"恒 0"（现有 agent 侧
   `GetLastResetDate` 越界返回 `currentDate` 就是反面教材）。
3. **周期边界**：服务端按配置时区计算"最近一次重置时刻"；小月无该日时沿用 agent 既有语义
   （顺延次月 1 日），保持行为可预期且文档化。
4. **周期累计**：维护每节点的"本周期用量"，跨重置时刻归零；**累计值继续单调增长**（面板口径不变）。
5. **agent 口径切换**：切换后 agent 应回报单调计数器（`--month-rotate 0`）；切换瞬间会出现
   "周期值 → 开机计数器"的跳变，必须**再基线**处理，不得把跳变当增量计入。
6. **可观测**：重置事件与再基线事件写审计日志（`auditlog`），便于事后核对。
7. **不动面板**：节点卡片与进度条继续读累计值；周期值只在接口/库中提供，留给后续决定是否展示。

## Acceptance Criteria

- [ ] 跨重置日用例：配置重置日 + 时区后，到达边界时**周期值归零**，累计值不回退（前后数值 + 命令输出）；
- [ ] 两种归零可区分：agent/机器重启导致的计数器归零**不**触发周期归零；跨周期边界**必须**触发；
- [ ] 越界配置（`0`/`32`/`-1`/非法时区）被**拒绝**并有明确错误信息；
- [ ] 时区边界可复核：给定配置能算出正确的 UTC 时刻（含小月顺延与 UTC+8 场景）；
- [ ] 切换 agent 口径时无异常增量（再基线生效，有单测覆盖）；
- [ ] 升级与回滚步骤写明，且说明"内存缓存 ⇒ 直接改库必须重启才生效"；
- [ ] 面板展示**未改变**（回归验证：卡片数值与进度条仍取累计值）。
